# Openboost v0.2.1

Bootstrap boundary correction release.

## Highlights

- Keeps Openboost `main` focused on reusable OpenCart AI bootstrap knowledge rather than experimental runtime tooling.
- Removes the experimental Python/PHP deployment runtime starter from the default branch while leaving the active deployment experiment in its own feature branch.
- Adds `docs/OPENBOOST_REPOSITORY_BOUNDARY.md` and enforces the same boundary directly from `AGENTS.md` and `AI_BOOTSTRAP.md`.
- Requires AI agents to classify incoming work as reusable bootstrap knowledge vs experimental/runtime implementation before merging branches.
- Requires reusable lessons from long-running experiments to be ported through a clean branch based on current `main` instead of wholesale-merging the experiment.
- Preserves deployment/OCMOD knowledge: stable canonical `<code>`, separate release `<version>`, safe owned legacy cleanup, full OpenCart 2.3 modification refresh, rollback/health-check/security rules.
- Fixes GitHub Release automation so normal `main` changes for an already-published root version are a successful no-op instead of attempting to move an immutable tag.

The `feat/opencart-deploy-bridge` branch remains intentionally separate for ongoing experimental Python/PHP deployment work.

See `CHANGELOG.md` for the complete history.
